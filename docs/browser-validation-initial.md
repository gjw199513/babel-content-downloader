## 浏览器和扩展环境

通过 `cua_repl` 看到的浏览器表面：

- Chrome：`cua_repl` 暴露了可用的浏览器表面，现有用户标签页较多。另建的验证标签页自动归入独立验证标签组，未改动既有标签页。
- Edge：桌面应用正在运行；Edge 账户入口的可见状态是“请登录”。Edge 没有作为 `cua_repl` browser provider 暴露，使用原生 app UI 检查。
- 当前没有看到 Babel 自有扩展已加载。Chrome `chrome://extensions/` 和 Edge `edge://extensions/` 的开发人员模式均已打开，页面均可见“加载解压缩的扩展”按钮。
- Chrome 和 Edge 中已有其他扩展属于既有环境，本轮未改动。没有点击“加载解压缩的扩展”，因为本轮尚无待加载的 Babel 构建目录。
- 本轮没有建立截图文件夹：`cua_repl` 提供了屏幕/AX 读取能力，但没有把截图 bytes 直接写入工作区的接口；文字证据和可复验路径已记录在本文件。

可复验的加载路径是：构建出独立的 `babel-content-downloader` 扩展目录后，在目标浏览器的扩展管理页保持开发人员模式，选择“加载解压缩的扩展”，再从欢迎页/任务页确认 bridge 与 MCP 状态。Chrome/Edge 都有相同的 MV3 开发者加载入口。实际加载动作应在构建产物可检查后单独验证；目前仅验证了入口可用。

`cua_repl` 的 `createBrowserTab` 没有暴露 `muted` 参数。为遵守“新开的公共媒体验证页默认静音”，初次观察时曾用 Chrome 右键菜单对 Bilibili 和小红书验证页选择 `Mute Site`；这是站点级设置，可能影响同一站点的其他标签页，不能描述为仅当前标签。YouTube 验证页当时已显示 `Unmute Site`，因此按原有站点静音状态保留。根据清理记录，随后关闭了本轮创建的 Bilibili、小红书测试页及唯一的 `about:blank` 临时页，并将前两站点的静音设置恢复到观察到的原始值；YouTube 状态未改动。YouTube 验证页的关闭状态没有单独记录。没有改变系统音量。未来扩展应在创建/导航任务标签页前后通过 Tabs API 明确设置 `muted: true`，并在复用标签页时再次保持该状态；Edge 应做同等处理。

## 公共页面证据

### YouTube（国际，单视频页）

样本：Rick Astley 官方公开视频，当前验证时的 URL 形状为 `https://www.youtube.com/watch?v=<videoId>`。该标签页后来被页面状态切换到另一个公开视频，以下只保留已观察到的结构证据，不把当前标签页标题当作稳定样本。

- 页面形态：单视频 watch route，不是 feed。
- 可见结构：`ytd-watch-metadata` 元数据容器；`h1.style-scope.ytd-watch-metadata` 标题；`<video>` 播放器（观察到时长约 213 秒）；作者/频道链接；hashtags 和描述文本。
- 字幕：播放器字幕按钮的可见名称为“无法显示字幕”，因此这一个样本不能证明可提取字幕。适配器应把字幕可见性作为单独能力检查，不应凭按钮存在假设有字幕。
- 访问：视频主体可见、可播放；未见 CAPTCHA、付费墙或私密提示。顶部可见的登录/电视提示不足以证明账号状态，记录为“页面公开可见，登录状态未断言”。
- 提取边界：以 `ytd-watch-metadata` 和主 `<video>` 为范围，避免把推荐列表和评论当作正文；作者链接和标题可作结构化字段候选。

### Bilibili（国内，单视频页）

样本：`https://www.bilibili.com/video/BV1GJ411x7h7/`（浏览器地址还带有站点生成的查询参数；本记录省略）。

该验证标签页在观察后发生了站点自动播放并切换到推荐视频；上面的结构与字段均来自切换前的目标页，当前标签页地址不应被当作该样本的稳定复验地址。任务标签页需要在创建/导航时静音并固定目标，避免 autoplay 把抽取范围带到推荐内容。

- 页面形态：单视频 route；页面下方另有“接下来播放”和推荐内容，不能与主内容混提。
- 可见结构/候选容器：主内容 AX 节点名为 `mirror-vdcon`；标题为 `【官方 MV】Never Gonna Give You Up - Rick Astley`；播放器包装名为 `playerWrap`，内部有“哔哩哔哩播放器”。这些是浏览器可见的 DOM/AX 线索，尚未承诺为跨版本稳定 CSS API。
- 播放器字段：播放/暂停、时长 `00:25 / 03:33`、清晰度 `1080P 高清 自动`、倍速、字幕、音量、设置、画中画和全屏等控件均可见。
- 元数据：可见播放量 `1亿`、发布时间 `2020-01-01 07:43:23`、标签、作者区和描述。页头可见“收藏/历史/创作中心/投稿”等账号相关导航，但没有记录用户名或账号 ID；身份状态仍按“未断言”处理。
- 字幕：页面正文可见中文（中国）、中文（中国香港）、日语、韩语、德语、俄语等字幕制作者条目。这证明该样本存在原生字幕线索，不等于已验证字幕文件下载；适配器需把字幕条目与主视频范围关联后再做能力验证。
- 访问：目标视频主体可见并可播放；未见 CAPTCHA、付费墙或私密提示。页面出现一个既有下载助手按钮，本轮没有点击。
- 提取边界：优先限定在 `mirror-vdcon`/`playerWrap`/描述区域；显式排除“接下来播放”、推荐和评论；Bilibili DOM 评估工具调用曾超时，故未将更细的 CSS 选择器标记为已验证。

### 小红书（国内，feed 页及详情阻塞）

样本 feed：`https://www.xiaohongshu.com/explore`。

- 页面形态：feed route，不是单条笔记。可见根容器 `#exploreFeeds`，可见 `.feeds-container`，可见 `.note-item` 约 30 个。
- 可见卡片结构：第一张卡片的可见文本包含 `Jev 把 computer use 提速了几十倍！` 和点赞数 `73`；公开作者标签已省略。卡片候选选择器为 `.note-item`、`.cover.mask.ld`、`.title`、`.author`、`.author-avatar`；卡片可见图片来自 `sns-webpic-qc.xhscdn.com`。搜索框可见 class 为 `.search-input`，placeholder 是站点当前展示的搜索提示。
- 链接形状：卡片提供 `/explore/<content-id>` 路径；页面生成的封面/标题链接还带 `xsec_token`、`xsec_source` 等签名查询。记录和持久化 canonical URL 时必须去掉签名；如果同一浏览会话要继续打开详情，只能临时沿用页面已提供的链接，不得把签名写入日志或 job artifact。
- 详情访问：用不带签名查询的 bare path 打开该卡片，浏览器显示“小红书 - 你访问的页面不见了”，页面带站点错误码 `300031` 和“当前笔记暂时无法浏览”提示。该证据只说明此样本的无签名详情入口受阻，不代表 feed 不能访问；适配器应把详情访问标为 `blocked/unknown`，保留 feed 与详情两种结果形态。
- 访问：feed 正常显示，没有可见登录、付费或 CAPTCHA 阻塞；未断言账号登录状态。没有使用页面隐藏状态、cookies 或用户资料来推断登录。
- 提取边界：feed 适配器应按 `.note-item` 建立单卡片候选，标题/作者/计数/封面作为可见字段；不要将整个 feed、隐藏脚本状态或作者账号信息当作正文。

## 结论和后续验证

这三页足以验证当前浏览器可见表面、国内/国际页面形态差异、主内容与推荐内容的边界，以及“小红书详情需要页面提供的签名链接”这一访问条件。它们还不能证明 Babel 的最终提取、字幕文件读取、媒体下载、MCP 传输或 job artifact 保存已经成功；这些需要扩展构建完成后，在独立任务标签页中继续验证。

下一轮实际扩展验证应检查：

1. MV3 扩展在 Chrome 和 Edge 的加载结果、欢迎页和 bridge/MCP 状态。
2. 创建任务标签页时 `muted === true`，导航和复用后仍保持静音；后台提取不触发声音。
3. 以 YouTube/Bilibili 单内容页和小红书 feed/详情受限页分别验证 adapter 选择、访问级别、主内容范围、字幕可用性和阻塞原因。
4. 结果只保留去签名的 canonical URL 与必要可复验字段，不写入 token、cookies、历史、账号或页面隐藏状态。
