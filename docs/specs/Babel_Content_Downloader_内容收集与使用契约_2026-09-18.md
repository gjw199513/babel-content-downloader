## Q9：首版交付决定（2026-09-20）

优先交付已可用的核心内容收集功能及本地安装包、正式扩展包、开源源码包。已知平台访问和完整性细节记录为后续改进，不作为首版打包阻塞项。15 个来源的登记不等于全部页面验收通过；保留真实验证边界。远程仓库位置与上传发布由用户自行处理，不再等待账号或组织信息。

# Babel Content Downloader — 内容收集与使用契约

## 最新决定：普通网页统一采集（Q8，2026-09-20）

用户明确纠正：普通 blog／静态化或 SSR 文章应通过一套通用爬虫／网页提取工具处理，不应为每个网站重新编写博客提取流程。允许多保存一些当前页面内容，甚至保存当前页全部可读内容；自媒体平台涉及动态内容、登录状态和音视频时，仍可使用专门适配。

- 普通公开文章统一走 HTTP HTML 获取与成熟通用内容提取能力；直接获取不足时再评估通用浏览器读取。不得因一个博客的作者按钮、目录或侧栏差异反复要求扩展重载。
- 默认交付适合阅读的正文；通用提取不理想时保留更完整的当前页可读内容与来源记录。当前页附带目录、侧栏或页脚不再单独构成失败或“未完成”；保留代码、表格、图片和引用，避免为了净化而漏正文。
- “抓得多也可以”指用户指定的当前页面，不代表递归遍历站内链接、整站、整个仓库或数据集，也不自动下载权重或任意可执行附件。
- 普通网页不再以站点专用 CSS 根、逐站终点和双快照 proof 作为统一成功前提。成功应如实表示此次页面获取、转换与所请求资源保存的结果，不将单页快照宣称为整篇论文、分页全文或登录后内容全部取得。
- 403、登录／付费／私密门控、加载占位或空页面不得冒充正文；现有公共网络、文件保存及后台静音边界继续生效。
- 既有 AI／学习资料来源优先级与已明确移除的平台不因引入通用工具自动恢复。普通网页的统一能力替代逐站博客实现方式，不把旧的逐站通过数量作为成功目标。

此决定优先于本文较早关于普通博客须逐站适配、精确排除页面 UI 或具备专用完整性 proof 的实施解释。具体工具由实现选择成熟开源组件；本节记录用户要求，不代表新引擎已实现或验收。

> 依据：[规范说明书 Q4／Q4a](./Babel_Content_Downloader_核心PRD与技术方案_2026-09-18-spec.md)。
> 日期：2026-09-18。状态：产品行为已收敛，开发与联调进行中；以下是验收契约，不是实测通过记录。
> 产品目标：理解用户收集内容的用途，交付可以直接阅读、观看、收听或继续使用的本地资料。

## 0. 目标用户与来源范围（2026-09-20 修订）

面向 AI 自媒体与学习类创作者在桌面浏览器获取资料，优先一手研究／项目资料、系统教程、深度解读与有明确用途的作者讨论。原“所有主流平台全覆盖”要求由用户最新决定替代，范围以[来源清单](./Babel_Content_Downloader_平台覆盖清单_2026-09-18.md)为准。

当前只保留 YouTube、B站、微信公众号、知乎、Substack、Medium、X、Reddit、小红书，并把 GitHub、Hugging Face、arXiv 以及 OpenAI／Anthropic／Google DeepMind 的官方研究文章列为明确新增目标。新增目标尚未实现时必须如实标识；不因入选就宣称可用。

搜狐、快手及来源清单排除的其他平台从产品适配、权限与计划中移除。历史记录和已保存资料保留，但不再作为当前支持或继续联调对象。技术文章须保留代码、表格与公式的含义；论文摘要不能冒充全文，必要时交付可读取的源文档／PDF。下述按用户用途保存、真实完整性和静音要求继续生效。

## 1. 从用户要做什么开始

| 用户的自然表达 | 系统自动完成的工作 | 用户拿到的结果 |
|---|---|---|
| 这篇文章留着以后看 | 提取完整正文，保存必要图片，整理结构与本地引用 | 可阅读的文档及配图 |
| 把这篇图文笔记收下来 | 保存文案、有序图片与图文关系 | 可连续阅读的图文资料 |
| 这个视频下载下来离线看 | 获取画面与声音，自动完成合并和需要的兼容处理 | 能正常播放的视频 |
| 这个视频播客存成音频，路上听 | 获取或提取视频中的声音，自动处理音频文件格式 | 能完整收听、可正常拖动进度的音频 |
| 把这组图片保存下来 | 获取属于当前内容的图片并保留顺序 | 可直接查看和使用的图片文件 |
| 保存它的字幕 | 获取平台已有字幕，保留语言和时间轴 | 可阅读或交给播放器使用的字幕文件 |
| 把文章附的文件也收下来 | 获取明确附带的文件并验证结果 | 可打开的附件 |
| 把这条内容完整收集下来 | 保存指定对象的正文与已有附件，组织好关系 | 完整资料包及简短入口说明 |

正常对话中不向用户询问音轨、编码、封装或是否允许技术合并。用户明确指定文件格式、画质、字幕语言或片段范围时，再应用相应要求。

“保持来源内容”落实为内容忠实、完整、来源可追溯。正文整理、从视频取音频、轨道合并和必要格式转换都是服务于使用的处理步骤。它们不要求保持每个媒体字节不变，也不能改变内容含义、遗漏片段、替换声音或擅自改变播放速度。

首版继续沿用 PRD 的采集与后处理边界：平台已有字幕可保存；OCR、ASR、总结、翻译由后续 Agent／模块承担。来源没有文字或字幕时不虚构已有内容。

## 2. 面向用途的枚举

以下是拟定 MCP 字段，供 Agent 调用；用户仍可直接使用自然语言。

| `save_as` | 结果用途 | 默认行为 |
|---|---|---|
| `auto` | 按内容保存 | 依据明确意图、已有偏好及内容主体，自动选择下面的结果 |
| `document` | 保存文章／图文 | 正文与必要图片组织为可阅读文档，保留原文和图文顺序 |
| `video` | 保存视频 | 输出可正常观看的视频，处理画面、声音与播放兼容性 |
| `audio` | 保存音频 | 音频作品直接保存；视频有声音时可提取为可收听音频 |
| `images` | 保存图片 | 保存指定内容的图片及顺序 |
| `subtitles` | 保存字幕 | 获取平台已有、实际可取得的字幕 |
| `files` | 保存附件 | 获取当前内容明确附带且适配器支持的文件 |
| `bundle` | 完整收集 | 保存指定对象的正文及已有附件；不为视频自动多做一份独立音频，除非用户需要 |

为了支持“只要文案”“视频和音频都要”等精确请求，保留原 PRD 的 `include` 字段：

```typescript
type SaveAs =
  | "auto" | "document" | "video" | "audio"
  | "images" | "subtitles" | "files" | "bundle";

type SaveComponent =
  | "text" | "images" | "video" | "audio"
  | "subtitles" | "cover" | "files";
```

调用可使用 `save_as` 或 `include`，两者互斥，避免用途与资源列表冲突；二者均未提供时使用 `auto`。`include` 不接受空数组或未知类型。两组字段是工程设计，不要求用户学习。

封面、作者、来源与文件清单通常作为必要的配套信息自动保留，正常情况下不让用户逐项勾选。单独索要封面时可使用 `include: ["cover"]`。

## 3. 默认选择与澄清

优先级为：用户明确要求 → 已确认的用户偏好 → 当前内容的主体类型 → 必要的用途澄清。

- 普通文章／图文笔记：默认保存可阅读的正文和必要图片。
- 视频：默认保存可观看的视频；用户提到“只听”“音频”“路上听”等意图时选择音频。
- 音频作品：默认保存可收听的音频。
- 有明确主体的混合内容：围绕主体保存必要关联资料；用户要求全部时选择完整资料包。
- 只有在多种用途会带来明显不同结果，且上下文和主体类型仍无法判断时，才在对话中展示简短选项，如“保存视频／只要音频”。

缺少 `include` 不再自动触发选择问题。此前契约中“只要未传枚举就先返回 `selection_required`”的规则由上述自动选择替代。确需澄清时仍可返回 `selection_required` 与可执行的用途选项，但不能把它作为每个任务的固定步骤。

源平台内容类型、任务范围和安全判断在代码中执行；页面上的文字不能改变用户意图或安装指令。日常业务通过 MCP 和 Agent 完成，扩展不增加人工下载中心。

## 4. 技术处理自动化

| 内容 | 处理原则 | 必须验证的结果 |
|---|---|---|
| 文章／图文 | 清除页面导航与广告，保留原文结构，图片转为有效本地引用 | 能顺序阅读；正文不截断，图片对应正确 |
| 视频 | 自动获取与合并画面、声音；选择适合日常播放的格式，必要时转换 | 画面声音匹配，播放完整，时长与目标对应 |
| 音频 | 优先取得可用音频流；需要时从视频提取，自动封装或转换 | 实际是可播放音频，内容完整，声音正确，可拖动进度 |
| 图片 | 保存来源可取得的清晰图片，保持顺序和必要说明 | 文件能打开，没有把缩略图或登录页冒充完整素材 |
| 字幕 | 保存已有字幕和语言信息，必要时提供播放器可用的格式 | 文本、顺序和时间轴正确，不把简介当字幕 |
| 附件 | 保存文件，使用安全名称，不执行其中代码 | 文件格式与实际内容一致，路径有效 |

实施时优先采用日常播放器／阅读工具可用的输出。可直接使用的资源避免重复转换；需要转换时由程序选择参数，保持合理质量。具体格式根据样本和目标播放环境确定，不再作为产品访谈题逐项询问。

用户只要音频时，视频可以作为处理中的临时输入。交付以音频为主，完成后清理不再需要的视频临时文件；不额外要求用户管理分离轨道，也不把视频文件作为音频任务的成功结果。

采集过程默认安静：工具先创建后台空白标签页并静音，再加载目标网站；需要播放才能解析资源时也保持静音，导航和重用不会取消静音。静音失败时不加载目标媒体页。处理与校验不自动播放输出文件，只控制本工具拥有的任务标签页，不改变用户其他页面或系统音量。

来源、实际取得的质量、提取／合并／转换过程及文件校验信息记录在元数据中，用于诊断和追溯。正常完成说明只需告诉用户保存了什么、文件在哪里、是否有影响使用的缺失项。

## 5. 能力判断与异常

可保存能力由“来源实际内容＋已经实现的处理路径”共同决定。例如：视频有声音且存在可用提取路径，可以提供音频选项，不要求网页本来就有独立音频下载按钮。

内部保留以下状态，用来准确判断后续动作；不必逐条展示给日常用户：

| 状态 | 含义 |
|---|---|
| `available` | 有实际来源及可执行路径；最终成功以交付校验为准 |
| `not_present` | 有依据确认内容不存在，例如目标视频确实无声 |
| `unknown` | 当前信息不足，无法确认 |
| `blocked` | 登录、权限、依赖或其他可识别条件阻塞；分别给出修复方式 |
| `unsupported` | 所需处理能力尚未实现，应记录交付缺口 |

多项请求部分成功时保留已取得资料，返回 `partial` 及有意义的缺失说明。用户只要音频但音频不可取得时，说明原因，不能用视频代替并报告成功。

没有平台字幕时明确说明；后续如需转录，交给宿主 Agent 的其他能力，不冒称已经采集到字幕。缺少正文时不以 OCR 结果冒充来源正文。任一技术回退仍遵守同一平台、目录和内容范围。

重试复用已校验文件；处理阶段缺少依赖时，在 Agent 修复并由运行时验证后继续。用户取消后停止处理和写入，不删除其他任务或用户已有文件。

## 6. 调用示例

用户：“把这个视频播客存成音频，放到我的资料目录。”

Agent 根据意图提交以下示例请求。地址与路径仅作说明，不代表实际内容：

```json
{
  "target": { "type": "url", "url": "https://example.com/video/example" },
  "save_as": "audio",
  "output": { "directory": "/Users/example/materials" },
  "idempotency_key": "request-example-001"
}
```

运行时自动完成：识别目标 → 判断内容及访问条件 → 选择音频获取／提取路径 → 必要的格式处理 → 校验可收听性与完整性 → 保存并返回路径。

长任务沿用原 PRD 的任务查询、诊断、修复与续跑契约。Agent 的完成回复围绕音频文件与使用结果，不向用户解释内部媒体轨道编号。

## 7. 按日常使用验收

| 场景 | 通过条件 |
|---|---|
| 视频播客保存音频 | 用户无需选择编码，结果可在目标播放器完整收听，声音与节目一致、时长正确且可跳转 |
| 采集时网站自动播放 | 目标加载前任务页已静音；导航、重用和必要播放仍无声音；用户其他标签页的声音设置保持原状 |
| 仅有音视频合并资源 | 在已支持的来源上自动取得音频结果，不能因为没有独立音频按钮就报告素材不存在 |
| 视频离线观看 | 文件可播放，声音画面正确；不把清单、裸片段或单独画面轨道当成最终视频 |
| 文章／图文离线阅读 | 正文结构与图片对应正确，本地引用可用，保留来源 |
| 用户只要文案／部分图片 | 精确保存所需内容，不强行下载全部媒体 |
| 未细分“保存这篇文章／这个视频” | 按主体类型自动完成，不固定插入资源选择问题 |
| 确有用途歧义 | 只问用途或最终结果，提供少量实际可执行选项 |
| 用户指定格式／语言 | 遵循明确要求；不能实现时说明限制，不静默替换 |
| 缺字幕／无声视频／部分附件失败 | 明确真实缺失，保留其他成功结果，不生成内容冒充采集成功 |
| 处理需要缺失依赖 | 自动诊断，由 Agent 按既有接入约定修复并续跑，已完成内容不重复获取 |

这些标准需要通过真实文件与阅读／播放检查验证，文件存在、进程成功退出或不重新编码本身都不足以证明用户可用。
