# Babel Content Downloader — AI／学习资料来源清单

## 最新决定：普通网页统一采集（Q8，2026-09-20）

用户明确纠正：普通 blog／静态化或 SSR 文章应通过一套通用爬虫／网页提取工具处理，不应为每个网站重新编写博客提取流程。允许多保存一些当前页面内容，甚至保存当前页全部可读内容；自媒体平台涉及动态内容、登录状态和音视频时，仍可使用专门适配。

- 普通公开文章统一走 HTTP HTML 获取与成熟通用内容提取能力；直接获取不足时再评估通用浏览器读取。不得因一个博客的作者按钮、目录或侧栏差异反复要求扩展重载。
- 默认交付适合阅读的正文；通用提取不理想时保留更完整的当前页可读内容与来源记录。当前页附带目录、侧栏或页脚不再单独构成失败或“未完成”；保留代码、表格、图片和引用，避免为了净化而漏正文。
- “抓得多也可以”指用户指定的当前页面，不代表递归遍历站内链接、整站、整个仓库或数据集，也不自动下载权重或任意可执行附件。
- 普通网页不再以站点专用 CSS 根、逐站终点和双快照 proof 作为统一成功前提。成功应如实表示此次页面获取、转换与所请求资源保存的结果，不将单页快照宣称为整篇论文、分页全文或登录后内容全部取得。
- 403、登录／付费／私密门控、加载占位或空页面不得冒充正文；现有公共网络、文件保存及后台静音边界继续生效。
- 既有 AI／学习资料来源优先级与已明确移除的平台不因引入通用工具自动恢复。普通网页的统一能力替代逐站博客实现方式，不把旧的逐站通过数量作为成功目标。

此决定优先于本文较早关于普通博客须逐站适配、精确排除页面 UI 或具备专用完整性 proof 的实施解释。具体工具由实现选择成熟开源组件；本节记录用户要求，不代表新引擎已实现或验收。

## 选择原则

服务 AI 自媒体与学习类创作者在电脑上收集资料：一手信息、可复用的技术内容、系统教程与深度解读优先；作者动态和应用案例作为补充。按来源和具体页面的用途选择，不按用户年龄、平台总流量或适配难易作判断。平台入选也不等于每篇内容都高质量，用户指定目标仍是采集边界。

只处理指定公开免费内容及直接附件，默认不抓主页、推荐流、评论区、整站、整个仓库或整个数据集。付费／私密／DRM 和访问策略边界不变；日常用途、自动处理和静音要求沿用[内容收集与使用契约](./Babel_Content_Downloader_内容收集与使用契约_2026-09-18.md)。

## 实施与验收顺序

1. 先完成移除：生产注册、coverage、host permissions、content script matches 和平台专用代码同步收窄；排除 URL 必须不能匹配生产适配器，历史恢复也不能获得旧平台网络权限。
2. 保留来源的回归转向 AI／学习资料样本：优先 X、YouTube／B站、公众号／知乎与长文，不再执行搜狐／快手或其他已移除来源的任务。
3. 实现一手资料来源：先 GitHub、Hugging Face、arXiv，再三家官方研究博客；分别固定单内容边界和成功判据。顺序不改变上述六项的目标地位。
4. 按用途交付：正文结构、代码／表格／公式、附件顺序与来源完整；视频／音频经过完整静默解码及跳转校验。技术页面如只能保真保存原文件，应交付该文件并明确可读范围；摘要不等于全文。
5. 每个来源逐项记录 URL／内容 ID、用途、访问前提、版本、文件哈希、缺项和真实证据；fixture、构建和单个成功样本不能提升为整站全面通过。

当前实现及逐样本结果见项目的 `docs/platform-status.md`；已移除平台的旧成功或失败均不计入本轮验收分母。
