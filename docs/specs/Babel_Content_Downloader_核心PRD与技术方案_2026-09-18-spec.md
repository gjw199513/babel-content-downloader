# Babel Content Downloader — 规范说明书

## 最新决定：普通网页统一采集（Q8，2026-09-20）

用户明确纠正：普通 blog／静态化或 SSR 文章应通过一套通用爬虫／网页提取工具处理，不应为每个网站重新编写博客提取流程。允许多保存一些当前页面内容，甚至保存当前页全部可读内容；自媒体平台涉及动态内容、登录状态和音视频时，仍可使用专门适配。

- 普通公开文章统一走 HTTP HTML 获取与成熟通用内容提取能力；直接获取不足时再评估通用浏览器读取。不得因一个博客的作者按钮、目录或侧栏差异反复要求扩展重载。
- 默认交付适合阅读的正文；通用提取不理想时保留更完整的当前页可读内容与来源记录。当前页附带目录、侧栏或页脚不再单独构成失败或“未完成”；保留代码、表格、图片和引用，避免为了净化而漏正文。
- “抓得多也可以”指用户指定的当前页面，不代表递归遍历站内链接、整站、整个仓库或数据集，也不自动下载权重或任意可执行附件。
- 普通网页不再以站点专用 CSS 根、逐站终点和双快照 proof 作为统一成功前提。成功应如实表示此次页面获取、转换与所请求资源保存的结果，不将单页快照宣称为整篇论文、分页全文或登录后内容全部取得。
- 403、登录／付费／私密门控、加载占位或空页面不得冒充正文；现有公共网络、文件保存及后台静音边界继续生效。
- 既有 AI／学习资料来源优先级与已明确移除的平台不因引入通用工具自动恢复。普通网页的统一能力替代逐站博客实现方式，不把旧的逐站通过数量作为成功目标。

此决定优先于本文较早关于普通博客须逐站适配、精确排除页面 UI 或具备专用完整性 proof 的实施解释。具体工具由实现选择成熟开源组件；本节记录用户要求，不代表新引擎已实现或验收。

## 需求 (Requirements)

### 功能需求

以下结合原文基线（PRD §§1–14、17–20）与本次用户访谈；用户最新澄清优先于早期访谈中的实施解释：

- R00：产品核心价值是帮助用户收集内容并使用。Agent 理解“阅读、观看、收听、留存素材”等意图，插件自动选择适当的采集与格式处理方式，最终交付能直接使用的本地文件。
- R01：产品名称为 Babel Content Downloader／巴别塔内容下载器；仓库与 MCP 服务标识为 `babel-content-downloader`，工具前缀为 `babel_content_`。
- R02：独立提供一个浏览器扩展及配套最小本机运行时，通过标准 MCP 供本地 Agent 调用；不依赖 DSH 或助学系统运行。
- R03：用户安装扩展后，将欢迎页接入指令交给 Agent，由 Agent 完成必要桥接、MCP 配置与真实浏览器连通验证；业务依赖按需补齐。
- R04：采集输入是明确 URL 或浏览器标签引用，默认围绕一条内容及其附件执行。多个链接可由 Agent 逐个提交；帖子串必须指定边界。
- R05：首版面向 AI 自媒体与学习类创作者，在桌面浏览器收集指定的公开免费资料，优先一手技术资料、系统教程、长文解读和作者讨论。2026-09-20 的 Q6 替代早期“所有主流自媒体平台都覆盖”的要求；平台数量不再是交付目标。
- R05a：当前范围固定为 15 个明确来源：GitHub、Hugging Face、arXiv、OpenAI 官方研究文章、Anthropic 官方研究／工程文章、Google DeepMind 官方研究博客；YouTube、Bilibili、微信公众号、知乎、Substack、Medium；X、Reddit、小红书。具体入口和内容边界见平台清单。该名单是助手按用户新目标作出的实施选择，不假称用户逐一点名。
- R05b：搜狐、快手明确退出；同时移除泛资讯／泛娱乐分发平台及原 13 个防遗漏候选。移除包括平台注册、访问权限、内容脚本注入、平台专用逻辑、当前覆盖列表和后续计划，不以 disabled／pending 保留回流入口；历史记录与用户已保存文件不删除。
- R05c：以[平台覆盖清单](./Babel_Content_Downloader_平台覆盖清单_2026-09-18.md)的明确目标为唯一范围依据，不再自动补齐“主流平台”或添加兜底网站。新增来源必须说明它如何补充当前资料需求、限定消费页面路径，并完成单独适配与真实验收；可分批实施，待实现与已可用必须区分。
- R05d：技术资料必须保留代码缩进、链接、表格和公式所承载的信息；若当前文档模型不能忠实呈现，应保存合法可取得的原始文档／PDF，或明确缺项，不能把摘要或压平的正文冒充完整论文／技术文档。GitHub 不默认克隆仓库，Hugging Face 不默认下载模型权重或数据集。
- R06：正常采集由一个高层 `babel_content_collect` 调用驱动，代码完成路径选择、必要页面操作、读取、下载、校验和保存。
- R07：拟定工具包括 `check`、`collect`、`job_get`、`job_resume`、`job_cancel`、`jobs_list`、`browser_observe`、`browser_act`，统一加 `babel_content_` 前缀；观察与操作仅用于明确任务。
- R08：保存到用户授权的本机目录。完整资料包包含 `content.md`、`metadata.json`、`assets.json` 和实际附件；正文使用相对附件引用。用户要听音频或看视频时，优先返回可播放的目标文件，来源与清单作为旁车信息，不要求用户理解内部目录结构。
- R09：原图与网页文字分别记录；采集层不自动执行 OCR、ASR、摘要或翻译。用户明确需要文字且已有字幕/正文不足时，允许 Agent 按《ASR 后处理移植 Spec》运行本地派生后处理，且不得覆盖原始内容。
- R10：任务状态、检查点与附件清单持久化；长任务返回任务引用。缺依赖时给出结构化诊断，宿主 Agent 修复、运行时复检后续跑。
- R11：区分 `succeeded`、`partial`、`failed`、`cancelled` 和执行中的 `blocked`；仅所请求组件全部校验通过才报告成功。无法判断完整性时明确记录未知。
- R12：支持幂等重试、冲突处理、任务取消与重启恢复；保留已完成附件，不覆盖用户资料，不误删其他任务文件。
- R13：浏览器实例、客户端与任务标签有明确归属；默认不抢焦点，不刷新、关闭或导航用户原有页面。
- R13a：用户要求采集音频时避免网页声音影响日常使用。工具创建的采集标签页默认静音，先建立空白后台页并静音，再加载目标；导航、重用和必要播放均保持静音。仅控制工具拥有的任务标签，不修改其他页面或系统音量。静音失败时不加载可能自动播放的目标页，返回可诊断状态。
- R14：欢迎页提供接入说明、连接状态及暂停／撤销入口；不做人工下载中心、聊天窗口或独立桌面工作台。
- R15：用户 Q2 确认公开开源，按可供他人安装使用的独立产品准备源码、浏览器扩展和本机运行时；不将个人环境中可运行作为公开交付的全部标准。
- R16：开源交付包含构建与安装说明、Agent 接入与诊断说明、平台支持状态、版本记录、许可证及第三方来源说明；软件包、仓库和商店地址只使用实际已建立的入口。
- R17：用户 Q3 选择先交付开源安装包：源码、可通过浏览器开发者模式加载的扩展包，以及供 Agent 完成本机运行时安装和 MCP 接入的材料。商店上架放到后续，不作为首版完成条件。
- R18：用户 Q4 要求按保存内容的类型建立枚举，Q4a 进一步明确以使用习惯和用途为中心。Agent 根据用户意图选择“文章／图文、视频、音频、图片、字幕、附件”等结果；枚举是调用与呈现能力，不能变成每次必经的逐项选择步骤。
- R19：用户 Q4a 允许从视频保存音频，并澄清收集目标是方便使用。早期“原样”解释调整为忠实保存来源内容，不编造、不偷换内容；为阅读或播放而进行正文整理、音频提取、轨道合并、封装或必要格式转换由程序处理。采集请求不因此自动新增 OCR、ASR、摘要、翻译或内容克隆；按需的 Agent-side ASR 另见《ASR 后处理移植 Spec》。
- R20：实施设计将结果用途与内部资源枚举分开：`save_as` 表达用户想得到的结果；`include` 可精确指定 `text`、`images`、`video`、`audio`、`subtitles`、`cover`、`files`。音频可来自视频里的声音，文档可由正文和图片组织而成；保存能力应依据来源内容和可执行处理路径判断，不能只按现成文件扩展名列选项。
- R21：明确意图时直接执行；普通“保存这篇文章／这条视频”按主体类型自动处理；只有上下文和内容类型仍不能确定用途时才展示简短选项。Agent 不询问用户编码、封装、是否允许分离音轨等内部细节。首版业务入口仍是 MCP，不增加必经的人工下载面板。
- R22：内容类型、用途枚举、默认行为、处理路径与验收场景见[内容收集与使用契约](./Babel_Content_Downloader_内容收集与使用契约_2026-09-18.md)。默认格式以日常阅读与播放为目标，用户明确指定格式时优先遵循；不把取得任意原始媒体轨道文件当作交付完成。

### 用户故事

- 用户给出笔记链接及保存目录，Agent 取得有序原文、图片和真实可读的本地路径。
- 用户指定公开视频，Agent 保存经过内容和媒体校验的文件；缺下载或合并依赖时修复后继续原任务。
- 用户指定帖子串边界，保存作者续帖与引用关系，不混入其他人的评论或扩大到整个主页。
- 用户要求保存当前页面，Agent 明确浏览器实例和标签后执行；目标不能确定时才询问。
- 用户收到部分成功报告后，能看清哪些附件已保存、哪些失败，并按原任务补做。
- 用户说“这个视频播客存成音频，路上听”，直接获得可播放、内容完整的音频文件，无须选择音轨、编码或封装方式。
- 用户说“这篇文章留着以后看”，获得正文与必要图片组成的可读文档，图片引用有效，来源可追溯。
- 用户说“这个视频下载下来离线看”，获得画面、声音与时长正确的可播放视频，技术合并与格式处理自动完成。

## 约束 (Constraints)

### 性能约束

- 原文基线：MCP 与桥接传输结构化结果和引用，不将视频或整批图片编码进模型上下文。
- 原文基线：同一来源低并发；任务应限制数量、单附件大小、总容量、执行时长、操作次数和重试次数。
- 实施默认：全局采集并发 2、同一来源并发 1、同一内容任务串行；可恢复失败最多自动重试 2 次。限流优先遵循明确的等待信号，无法按预算完成时返回可恢复状态。
- 长流程尽早返回任务引用；下载、格式处理和校验各自具有超时与取消机制。容量和执行预算由可配置策略控制，结合样本实测调整，不让未知大小触发无限下载，也不承诺未经测量的速度或成功率。

### 日常使用默认值

以下为依据用户目标作出的实施默认，无须用户逐项回答；可按明确任务要求覆盖：

| 项目 | 默认行为 |
|---|---|
| 保存内容 | 明确意图优先；未细分时按内容主体选择可读文档、可播放视频或音频，确实存在用途歧义才询问 |
| 音视频格式 | 自动选择适合日常播放的格式；能直接使用时保留，必要时转换；保持内容、顺序和正常速度 |
| 采集过程声音 | 任务页加载前静音，必要播放也静音；后台提取不自动播放输出文件，不改变用户其他页面的声音设置 |
| 画质与音质 | 选择来源可取得、适合正常观看／收听的质量，不做增强或多档重复下载；用户明确质量要求时遵循 |
| 字幕 | 显式请求时保存平台已有字幕；普通视频保存可在可取得时一并保留必要字幕，不运行转录生成 |
| 保存目录 | 使用用户指定目录；未指定时使用已确认授权的工作区 `materials/` 或已配置收集目录；两者都不存在时只询问保存位置 |
| 重复请求 | 同一任务及选择幂等复用已校验文件；用户要求重新获取时创建版本，不覆盖已有资料 |
| 任务临时数据 | 完成后清理不再需要的临时轨道；可续跑检查点默认保留 7 天；日志默认保留 7 天，均可配置；不自动删除最终资料 |
| 必須前台或登录 | 默认不抢焦点；需要时报告具体动作，保持其他独立任务可继续，不把全部流程重来 |

### 安全约束

- 原文基线：首版排除付费、会员／订阅独享、私密内容、DRM 绕过及未启用平台；不因登录、引擎回退或重定向自动扩大范围。
- 原文基线：仅提供内容读取所需操作，不提供发帖、评论、点赞、关注、购买、任意脚本或任意系统命令接口。
- 原文基线：凭据不进入 MCP 响应和日志；临时会话资料仅用于必要来源；本机通信需认证并绑定正确扩展实例。
- 原文基线：目录授权、路径穿越、符号链接、附件 URL 与重定向校验覆盖全部执行路径。
