## 1. 产品定位与核心原则

### 1.1 产品定义

Babel Content Downloader 是一个面向 Codex、Claude Code、DSH 等外部本地 Agent 的浏览器内容下载插件。用户提供内容链接、明确标签页或由 Agent 确认的具体目标；Agent 通过 MCP 调用，插件自动定位内容、按需操作浏览器、获取正文和附件，并保存到用户指定的本地目录。

首期重点是**已适配自媒体平台上的免费公开内容**，包括文案、帖子、图文笔记、图片、视频及可获取的原生字幕。以小红书、X 等为重点适配目标，实际可用能力以允许的访问方式与测试结果为准。

产品按“一条指定内容及其附件”交付，不是全网通用爬虫，不默认遍历整站、整个人主页或全部评论。未来可以通过独立适配器扩展经授权的课程内容，但课程专项适配、付费平台、会员和订阅专属内容均不属于首版交付。

### 1.2 核心原则

| 原则 | 具体要求 |
|---|---|
| AI 优先 | 正常入口是 MCP；不依赖人工下载按钮、资源列表或逐步操作教程 |
| 单一产品 | 用户只安装自己的一个浏览器扩展，不另外拼装多个第三方扩展 |
| Agent 完成接入 | 欢迎页提供可复制指令；Agent 安装最小桥接、配置 MCP、完成端到端连接验证 |
| 依赖按需补齐 | 插件提供诊断与验证；外部 Agent 安装缺失依赖、修复配置并继续任务 |
| 稳定流程写进代码 | 常规采集用一个高层动作完成；不要求 AI 每次重建全部浏览器操作步骤 |
| 内容完整交付 | 原文、图片、媒体与来源一起保存；缺失项和部分成功如实报告 |
| 模块独立 | 标准 MCP 优先；不绑定 DSH、某个 AI 客户端或助学系统 |
| 范围明确 | 仅执行启用的平台适配与明确目标；不因登录状态或回退引擎而扩大访问范围 |

### 1.3 与 Babel 系列及后续处理的关系

品牌属于 Babel 系列，运行上保持独立。插件不内置另一个聊天 Agent，不承包 OCR、ASR、总结、创作或完整学习系统。

```text
已适配平台的指定内容
        ↓
Babel Content Downloader：定位、读取、下载、校验与保存
        ↓
本地原始资料包与来源信息
        ↓
外部 Agent／其他 MCP：转录、OCR、整理及后续处理
        ↓
巴别塔助学系统或其他用户工作流程
```

下载资料只是获取原始输入，不等于已经完成理解或学习。后续模块复用同一资料格式，不重复实现平台采集。

## 2. 内容范围与平台边界

### 2.1 首版的内容对象

首版重点是已适配自媒体平台上的免费公开内容。顶层对象为 `ContentItem`，一次任务围绕用户指定的一条内容及其附件展开；帖子串等关联内容必须有明确边界。

内容类型可以扩展，不代表平台覆盖不设边界。通用正文提取和媒体发现只作为已启用适配器的内部能力，不提供“任意网站都能采集”的默认入口。

| 内容类型 | 需要保留的内容 | 重要限制 |
|---|---|---|
| 文章 | 标题、作者、正文结构、链接、正文图片、发布时间（可取得时） | 不将导航栏和推荐列表混为正文 |
| 社交帖子 | 原始文案、作者、内容 ID、发布时间、话题、媒体附件 | 不默认抓整个人主页 |
| 帖子串／Thread | 单条帖子的边界、作者、顺序、回复或引用关系 | 不把作者续帖和其他人的评论拼成同一篇原文 |
| 图文笔记 | 文字、图片顺序、原始说明、视频附件（如有） | 图片内文字不自动假装成已经识别的正文 |
| 视频 | 视频文件、描述文案、封面、可获取的原生字幕、基本元数据 | 不绕过 DRM，不承诺下载所有清晰度 |
| 音频 | 音频文件、标题、描述、来源与可获取的附属文本 | 复杂音频平台适配可后续补充 |
| 混合内容 | 按源顺序组织的正文、图片、音视频与引用块 | 一个内容对象可包含多类附件 |

平台评论、回复区、主页列表、收藏列表、搜索结果属于额外范围。默认采集用户明确指定的单条内容；需要扩大范围时，由 Agent 根据用户任务显式给出数量和边界。

### 2.2 “登录了可以读”怎样转成产品规则

产品目标是利用用户当前合法登录的浏览器会话，减少重复登录和手动导出 Cookie。

但以下三个概念不能合并：

| 维度 | 要回答的问题 |
|---|---|
| 内容可见性 | 是公众可见，还是私信、好友、私密群组或仅订阅者可见？ |
| 内容付费属性 | 免费，还是需要购买、会员或付费订阅？ |
| 采集许可与技术可行性 | 当前访问方式是否符合平台规则及内容授权？工具是否确实能取得完整内容？ |

**普通账号登录后可看的公开免费帖子，可以成为适配目标；“已登录”不是任意抓取权限。**首版不因为账户恰好购买了课程，就自动扩大到付费内容；也不因为私信免费，就把私信纳入范围。

### 2.3 首版的平台目标与核验状态

下面是需求优先级与验证范围，不是已实现的支持列表。

| 平台或来源 | 规划内容 | 当前在本方案中的状态 |
|---|---|---|
| 小红书 | 指定公开免费笔记的文案、图片和视频 | 用户明确的重点目标；做专项适配与规则核查，不声称已经实测可用 |
| X | 指定公开帖子、附图、视频及有边界的帖子串 | 用户明确的重点目标；有明确平台规则风险，须先落实允许的访问路径 |
| Bilibili、YouTube 等视频来源 | 公开免费视频及描述、封面、原生字幕 | 下载引擎验证目标；排除付费、会员专属内容，并核查平台与内容授权 |
| 已明确适配的自媒体文章、公开博客等内容来源 | 指定文章的正文、图片和来源 | 复用正文提取模块，不扩大成任意网站通用爬取 |
| 其他免费公开平台 | 与统一内容模型兼容的对象 | 后续按适配器接入，不宣称全量覆盖 |
| 课程平台／课程内容 | 后续经授权的课程正文、媒体与附属资料 | 课程专项适配留待后续；不列为首版能力 |
| 以付费课程、付费专栏为主的平台 | 课程、会员文章等 | 首版不接入，包括不通过通用提取器变相接入 |

**平台接入条件：**X、小红书等是重点需求，不是已实现并已获准使用的支持清单。上线前须分别核验当前平台规则、允许的访问方式、内容范围和账号实测结果。X 的访问路径应对照其官方自动化规则确认。[R31]

“免费公开”“只读”“已登录”均不能代替这些核验；第三方开源工具的存在也不等于平台已经许可本产品的访问方式。

### 2.4 首版明确排除

不做付费墙绕过、DRM 解密、盗用登录态、验证码绕过、隐私内容批量归档、无限主页爬取、账号池轮换规避限制或自动购买内容。

收费平台的免费试读与试听也不作为首版扩范围的理由。混合型平台则按内容类别和适配范围判断：只处理已核实的免费公开区域，付费区域直接停下。

### 2.5 内容使用边界与课程扩展

免费公开用于限定产品范围，不作为自动获得下载、使用或再发布授权的依据。平台访问条件与内容使用权限分别核验，相关内容使用边界可参考 WIPO 的说明。[R30]

产品应保留作者、来源和采集时间，不默认重新发布、去署名或去水印。这些措施有助于资料追溯，但不能替代授权判断。

课程是后续可选内容类型，主产品名称和统一资料格式不因此改变。课程扩展可以描述课程、章节、课时及其附件关系，但不在首版启用课程专项采集。

后续优先验证获得明确许可的公开课程内容；付费课程、会员或订阅内容须作为独立、显式启用的扩展另行评估。不能仅因用户已购买或登录就推定允许自动下载，首版也不能通过 `allow_paid=true` 等参数开放这些能力。所有适配和回退路径必须执行同一范围检查。

## 3. 用户场景与交付结果

### 3.1 视频到指定目录

用户说：“把这个公开视频下载到项目的 `materials/videos`，之后帮我整理。”

Agent 解析目标和目录，调用采集工具。插件自动判断直取或浏览器路径，必要时自动打开任务标签页；缺少下载或合并依赖就返回诊断。Agent 处理依赖后继续任务，最后得到真实存在、校验过的文件路径。整理工作由 Agent 的其他能力完成。

### 3.2 小红书图文笔记

用户说：“把这篇笔记的文案和图片保存下来。”

在适配与授权条件满足的前提下，输出一份有序正文和图片资料包。不只返回图片链接，也不只保存截图。若正文主要在图片中，先完整保存原图，并标注 OCR 未执行；后续可由外部 Agent 处理。

### 3.3 X 帖子或帖子串

用户说：“保存这条帖子和作者后续的几条续帖。”

先通过允许的访问路径获取指定范围。返回各帖子的原文、顺序、作者与来源，不自动扩大到全部评论、整个主页或用户关系图。访问路径不符合当前规则时返回明确阻塞状态，不悄悄切换成未经允许的抓取方式。

### 3.4 当前浏览器页面

用户说：“把我正在看的内容收下来。”

Agent 应先定位指定浏览器实例和标签页。只有一个明确候选时可以直接处理；多窗口、多配置文件或多个候选并存时，先通过观察工具判定，确实无法判定才询问用户。不以“哪个页面最像视频”代替目标识别。

### 3.5 只有模糊标题，没有链接

搜索与目标选择先由外部 Agent 完成。Babel Content Downloader 接收可执行目标后再开始采集，避免下载第一个搜索结果当作成功。

### 3.6 多个链接

首版可以由 Agent 逐个提交任务，不必先开发复杂批量工作台。后续批量接口要保留逐项状态、失败原因和数量上限，不能一条失败就掩盖其他任务的结果。

## 4. 首次安装与 Agent 接入

### 4.1 面向用户的体验

```text
安装 Babel Content Downloader 浏览器扩展
          ↓
欢迎页：复制一句接入指令
          ↓
粘贴给 Codex／Claude Code 等本地 Agent
          ↓
Agent 安装最小桥接组件、配置 MCP、验证连接
          ↓
Agent 返回简短说明
          ↓
以后直接给链接和保存要求
```

不要求用户阅读一套终端安装教程；也不要求用户额外安装原版 mcp-chrome、猫抓等扩展。

### 4.2 欢迎页文案建议

> **Babel Content Downloader 已安装，下一步交给你的 AI。**
>
> 复制下面的接入指令，发送给 Codex、Claude Code 等本地 Agent。
>
> **［复制接入指令］**
>
> 状态：等待 Agent 连接。

界面只需要接入提示、连接状态、必要的权限说明，以及暂停／撤销连接等控制。没有人工下载中心不等于用户不能停止插件。

### 4.3 复制给 Agent 的指令

以下是设计模板。正式产品自动填入真实发布地址、扩展 ID 和版本；当前占位符不是已存在的安装地址。

> 请按照【Babel Content Downloader 官方接入说明的版本化链接】，为我已安装的 Babel Content Downloader（巴别塔内容下载器）浏览器扩展完成本机接入。扩展 ID：【自动填入】；扩展版本：【自动填入】。请检测当前环境，从说明指定的可信来源安装必要桥接组件，注册该扩展，添加当前客户端的 MCP 配置，并验证实际浏览器连通性。保留已有 MCP 配置，不覆盖其他服务；必要安装操作在已有授权范围内执行。接入完成后，只告诉我如何提供内容链接和保存目录。业务依赖后续按任务需要安装，不要预装整套媒体处理环境。

扩展 ID 是识别信息，不是密码。长期连接密钥不放进这段复制文本，也不随聊天传播；本机配对凭据应通过可信的本地注册和握手建立。

### 4.4 开发时必须提供的接入材料

| 材料 | 用途 |
|---|---|
| `docs/agent-setup.md` | 面向 Agent 的权威安装、验证、恢复说明 |
| `bootstrap-manifest.json` | 固定版本、可信包名／下载来源、校验信息、平台支持范围 |
| 客户端配置模板 | 分别描述 Codex、Claude Code 等的接入方法，不假设配置格式相同 |
| 诊断与注册命令 | 在 MCP 尚未连上时检查最小运行条件、注册 Native Host |
| 连接验证方法 | 识别真实扩展实例、版本和会话，完成端到端测试 |
| 卸载与回滚说明 | 仅撤销本项目配置，不删除其他 MCP 或无关依赖 |

这些材料属于本项目的交付内容。把安装工作交给 Agent，不等于让 Agent 凭空猜仓库、包名和执行命令。

### 4.5 首次接入与运行中修复是两条流程

MCP 完全未连接时，不能通过尚不存在的 MCP 返回“缺桥接程序”。因此：首次接入依靠上述官方说明和最小引导程序；接入之后的业务依赖问题，才通过 MCP 结构化诊断解决。

mcp-chrome 的桥接安装、注册与客户端配置可作为改造参考。自动接入、实例识别和连接验证作为本项目需要实现并测试的能力，不将上游项目等同于完整交付。[R01]

Chrome Native Messaging 使用 `allowed_origins` 限定允许连接的扩展。改造后要注册 Babel Content Downloader 自己的扩展 ID，而不是原项目 ID。[R21]

### 4.6 怎样才算安装成功

仅“依赖安装命令返回成功”或“配置文件写入成功”不算接入完成。至少验证：

1. 当前客户端能发现 Babel Content Downloader 的 MCP 工具。
2. 最小运行时能确认扩展实例及版本，而非仅自身存活。
3. 在本地测试页完成一次读取，收到对应请求的真实结果。
4. 下载依赖缺失时，基础诊断与文字读取仍然可用。

Codex 与 Claude Code 都提供 MCP 接入，但配置位置、作用域和加载行为应按各自当前官方文档处理，不能用一份 JSON 强行套用所有客户端。[R28][R29]

若客户端需要重载或开启新会话才能发现新工具，应明确报告 `awaiting_client_reload`，不能提前宣称已经连通。必要的系统授权由用户确认，不能通过关闭安全机制来实现所谓一键安装。

### 4.7 成功后给用户的短说明

> **Babel Content Downloader 已连接。**
>
> 把内容链接和保存位置发给我即可，例如：“把这篇笔记的文案和图片保存到当前项目的 materials 目录”，或“下载这个公开视频到指定文件夹”。也可以指定当前浏览器页面。需要额外依赖时会按需检查和处理；需要登录或额外授权时会提示你。

## 5. 职责划分

| 角色 | 负责事项 | 不负责事项 |
|---|---|---|
| 用户 | 目标、目录、必要授权 | 找媒体地址、选下载参数、常规安装排错 |
| 外部本地 Agent | 理解意图、调用 MCP、安装缺失依赖、修复配置、后处理 | 不应每次重新发明一整套采集步骤 |
| Babel Content Downloader 浏览器扩展 | 浏览器会话、任务标签、页面观察、必要交互、内容和媒体发现 | 不运行另一套内置聊天 Agent，不充当通用本机安装器 |
| Babel Content Downloader 最小本机运行时 | MCP 接入、浏览器桥接、任务状态、目录写入、引擎调用和诊断 | 不提供独立桌面工作台，不包办所有系统依赖 |
| 第三方引擎 | 已有媒体解析、下载、合并等具体能力 | 不决定产品授权策略，不直接接受页面提供的任意命令 |
| 后续学习／内容模块 | 转录、OCR、总结、练习与知识加工 | 不成为采集原始资料的强制前提 |

“一个插件”指一个对用户交付的产品，不意味着所有可执行代码必须在浏览器扩展沙箱中运行。配套运行时由 Agent 接入和管理，用户不需要打开它的窗口或维护多个服务。

首版以浏览器、本机运行时和 Agent 位于同一台电脑为基准。云端 Agent、容器或 WSL 的路径和浏览器连接不能默认与宿主机等价；发现这种情况要报告运行上下文差异，不把宿主机文件路径当成远端已收到文件。

## 6. 系统架构与通信

### 6.1 单一产品内的两个执行环境

```text
用户
  │ 给出内容目标与保存要求
  ▼
Codex／Claude Code／DSH 等本地 Agent
  │ 标准 MCP
  ▼
Babel Content Downloader 最小本机运行时
  ├─ MCP 工具与结果封装
  ├─ 内容任务、状态存储、续跑
  ├─ 平台／授权范围检查
  ├─ 本地目录与资料包写入
  ├─ 依赖检测、结构化诊断
  └─ 已安装引擎调用
       ├─ yt-dlp
       ├─ FFmpeg／ffprobe（按需）
       └─ 其他经核验的可选引擎
  │
  │ 浏览器桥接
  ▼
Babel Content Downloader 浏览器扩展
  ├─ 已登录浏览器实例识别
  ├─ 任务标签页管理
  ├─ 页面观察与受控交互
  ├─ 正文、图文与帖子结构提取
  └─ 媒体请求／播放清单发现
  │
  ▼
用户明确指定、符合范围的平台内容
```

这是逻辑模块图，不是要求用户部署多个应用。浏览器端与本机端可以在同一仓库中开发、统一版本发布，内部通过接口隔离。

### 6.2 连接基础与复用边界

以 mcp-chrome 为首选连接骨架候选，复用范围聚焦浏览器会话连接、页面操作、内容读取、网络捕获和本机桥接；选定版本后核对对应实现与许可证。[R01]

采用方式是 fork 或提取相应模块，做成 Babel Content Downloader 自己的扩展和运行时，不让 Agent 去点击原版 mcp-chrome 或猫抓的界面。原项目中的浏览历史、书签修改、语义搜索等非必要功能不直接全部带入。

mcp-chrome 不能被当成已经通过安全审计的成品。发布前需要检查并补齐认证、任务权限、运行时生命周期与异常恢复；不依赖 README 的宣传性对比来证明这些能力已经满足要求。

### 6.3 传输与启动策略

建议首版先验证 mcp-chrome 已有的本机桥接关系，优先测试本机 Streamable HTTP 接入；需要时提供 STDIO 兼容入口。MCP 规范定义了这两种传输方式，但它们与浏览器 Native Messaging 不是同一个协议。[R27]

| 连接 | 目的 | 建议约束 |
|---|---|---|
| Agent ↔ 本机运行时 | 标准 MCP 工具调用 | HTTP 只绑定本机回环地址并认证；或使用 STDIO 入口 |
| 扩展 ↔ Native Host／桥接器 | 浏览器任务与结果交换 | 注册自己的扩展标识；实例绑定；校验消息结构 |
| 本机运行时 ↔ 下载引擎 | 下载或后处理 | 固定参数构造、超时和进程管理，禁止任意 shell 字符串 |
| 扩展／引擎 ↔ 内容来源 | 获取指定内容 | 限定任务站点和附件来源，遵守适配器范围 |

Native Messaging 通道由扩展发起连接。本机程序不是在未注册、未授权的情况下随意控制任何扩展。[R21]

进程由配套启动机制按需管理，不要求用户开终端维持运行。Native Host 与 MCP 主进程是否共用、多个客户端如何共享单个实例，应在最小原型阶段验证。可以存在内部协议适配程序，但不要因此产生多个用户可见产品。

浏览器关闭、桥接服务未启动、客户端需要重载属于接入状态，不应伪装为业务依赖缺失。连接都未建立时，外部 Agent 使用接入诊断路径排查，不能期待一个离线 MCP 还能返回工具结果。

### 6.4 控制信息与大文件分开

MCP 和浏览器桥接主要传递任务、内容结构、资源引用及状态。视频、大批图片等不作为 Base64 长文本塞入模型上下文。

大文件直接落到本机受控目录。扩展必须先下载时，由本机运行时接续整理；需要分块传输的场景另设文件通道，不混入普通工具文本响应。

### 6.5 对 DSH 的关系

首版不依赖 DSH 内部插件协议。后续 DSH 原生插件只负责界面展示、任务组合与资料导入，复用相同 MCP 和资料格式，不另写一套平台采集逻辑。

## 7. 自动采集与浏览器操作

### 7.1 自动路径选择

```text
接收 URL 或已确认的标签页引用
          ↓
规范化来源，匹配已启用适配器，检查内容范围与平台策略
          ↓
选择采集路径
   ┌──────┴───────────┐
   │                  │
已有可用直取路径      需要浏览器上下文
   │                  │
直接解析／下载       定位正确的浏览器实例
   │                  ↓
   │             复用明确指定的页面
   │             或创建专用任务标签
   │                  ↓
   │             观察、展开、加载、必要时播放
   │                  ↓
   │             提取正文／发现媒体
   └────────┬─────────┘
            ↓
按用户要求保存资料包，校验并返回结果
```

“直取优先”不意味着忽略用户明确指定的当前页面，也不意味着把登录后的页面换成匿名 HTTP 请求。需要浏览器会话的任务，应直接选择浏览器路径，避免无意义的失败。

### 7.2 任务标签页规则

能直取就不打开页面；必须打开时，在正确浏览器配置文件内创建任务标签页，默认不抢焦点。Chrome 标签 API 提供创建时的 `active` 参数，但后台页面的生命周期和执行状态仍要处理，不能保证所有站点永远无感加载。[R23]

任务标签必须记录 `job_id`、浏览器实例与标签所有权。只清理自己创建的标签，不关闭用户原来的页面；默认不刷新、导航或切换用户正在使用的页面。

网络监听先于导航或播放建立。已存在的页面若错过媒体请求，先检查 DOM 和可取得的资源记录；需要重新加载时，优先在任务标签中处理。

### 7.3 可以自动做的页面操作

在任务范围内进行导航、有限滚动、展开正文、切换图集、播放视频、选择目标分段或读取必要的 iframe。目标是完成明确内容的采集，不把本插件扩展成任意网站的全权限操作器。

后台标签被冻结、页面必须前台激活、站点需要登录或浏览器权限时，返回具体原因或按预先授权的策略处理。不能通过无限点击和刷新假装在推进任务。

### 7.4 不让 Agent 每次手工编排所有动作

正常路径是一条高层 `collect` 调用。URL 识别、正文展开、媒体捕获、下载和校验等稳定动作在代码里编排。

只有目标不明确、页面结构超出适配范围等情况，才开放任务级观察与受控操作给外部 Agent。页面上的广告、指令或隐藏文本不能修改这条编排的权限边界。

### 7.5 多客户端与多标签隔离

Codex 和 Claude Code 可能同时连接同一浏览器。本项目需要为任务绑定客户端会话、浏览器实例和标签引用，并对有副作用的页面操作加锁。不能让两个客户端轮流切换同一个任务标签，或关闭对方仍在使用的页面。

默认同一来源低并发，遇到明确限流退避并报告；不通过增加账号或绕过限制来提升吞吐。

## 8. 文案、图文与媒体获取

### 8.1 已适配内容的正文提取

建议以 **Defuddle** 为首选验证对象，以 **Mozilla Readability** 为对照或回退方案；需要自定义 HTML 转 Markdown 规则时使用 **Turndown**。Defuddle 提供主体内容提取和 Markdown 输出；Readability 提供正文抽取；Turndown 负责格式转换，并不负责判定哪一部分才是正文。[R13][R14][R15]

正文库用于已启用适配器内的内容提取，不因它能解析其他网页就自动启用新的平台。不要为同一页面无条件叠加所有库。测试正文完整度和结构后，确定默认路径；回退方案只在有明确失败信号时使用。

建议的正文流程：定位主体 → 保留结构和媒体关系 → 过滤无关区域 → 清理不安全 HTML → 转为 Markdown → 校验。

清理是删除导航、广告和不安全标记，不是改写原文、生成摘要或翻译。Readability 本身不是安全净化器，项目也建议处理不可信输入时搭配清理措施。[R14]

### 8.2 社交平台使用专项适配器

短帖子、多图笔记、引用帖、长文展开和帖子串不一定符合传统文章结构。通用正文库可能漏掉作者、图片顺序或帖子边界，因此需要专项适配。

小红书可以研究 `xiaohongshu-mcp` 的登录状态和平台操作结构，该项目公开 Go 源码并采用 Apache-2.0 许可；只提取与读取相关的实现思路，发布、评论等写操作不纳入本插件。[R17]

X 可以研究 `twscrape` 的数据模型作为字段参考，但它不是浏览器扩展，也不作为当前默认接入方案。其技术存在不改变 X 的自动化规则；不引入其中的账号池轮换模式。[R18][R31]

原生网络响应仅在符合平台规则且确有权限时作为可选数据来源，不能以“复现浏览器接口”为理由绕过发布前的授权检查。

### 8.3 图片不是附带几个外链就算完成

根据用户要求下载本地图片，并保留原始顺序、尺寸、说明和与正文的对应关系。能取得原图时优先原图，取得的只是缩略图则明确记录；失效外链不能伪装为已保存附件。

图片内的文字与网页 DOM 正文分开。未执行 OCR 时，设置 `ocr_status: not_requested` 或 `not_performed`，不编造图片里的文案。OCR 后续由外部 Agent 或其他模块调用，结果放入派生资料，不覆盖原图和原文。

`gallery-dl` 可作为后续图集下载的可选引擎，而不是读取一张图片也必须安装的基础依赖。采用时重新确认当前维护入口、所选版本与许可证。[R19]

### 8.4 视频与音频下载

| 情况 | 建议执行方式 |
|---|---|
| 已取得普通媒体地址 | 在会话与权限允许的前提下直接保存 |
| 平台链接可由引擎解析 | 调用 yt-dlp |
| 页面需要运行播放器才能出现资源 | 扩展完成必要交互并捕获资源，再交给下载模块 |
| 分离的音视频轨道需要合并 | 按需使用 FFmpeg |
| 已获得非 DRM 流媒体清单，主路径不适用 | 评估使用 N_m3u8DL-RE 作为可选后备 |
| 内容受保护或超出授权范围 | 停止，返回不支持或访问策略阻塞，不切换成绕过方案 |

yt-dlp 是主要媒体引擎候选，FFmpeg／ffprobe 用于需要的合并、后处理与校验。上游还列出部分平台依赖的 JavaScript 运行时及相关组件，因此依赖检测应由能力清单驱动，不能永远只写死 yt-dlp 和 FFmpeg 两项。[R04]

N_m3u8DL-RE 支持 HLS、DASH 等流媒体下载，可在具体案例确有需要时增加；不作为首版所有用户的必装项。[R06]

### 8.5 浏览器下载与指定目录

Chrome 下载 API 的 `filename` 是下载目录下的相对路径，不能用它直接写任意绝对路径。[R22]

因此，用户要求保存到项目指定目录时，默认由本机运行时执行最终落盘。必须利用浏览器会话下载的文件可以先落到受控暂存区，再由运行时验证并整理到目标目录。

不把“浏览器下载列表出现了记录”当成“项目目录里已经有完整文件”。最终返回位置必须经过文件存在性与完整性验证。

### 8.6 资源发现不等于完整文件

`blob:` 地址、播放器对象、一个 HLS 清单或若干片段都不是最终可交付文件。浏览器媒体发现需要与下载、音轨处理、清单有效性和文件校验衔接。

网页错误页、登录页、封面图、广告视频不得被错误地标记成用户要求的视频。清晰度、大小和时长来源不可靠时保留未知状态，不凭扩展名猜测。

### 8.7 字幕和转录的边界

平台已经提供且允许获取的字幕，可以作为原始附件一起保存。将音频识别成文字属于 ASR 后处理，不作为采集插件内置的必需能力。没有字幕应明确标注，不自动把视频描述当作完整转录。

## 9. MCP 工具契约

### 9.1 统一的内容级接口

MCP 服务标识使用 `babel-content-downloader`，工具前缀使用 `babel_content_`。核心动作是 `babel_content_collect`，输入用户指定的内容目标与保存要求，输出本地资料和结构化状态。

文案、图片、图文与视频共用接口，不为每个平台要求用户另外连接一个 MCP 服务。名称、字段和示例是拟定开发契约，不代表已发布接口。

### 9.2 第一版建议工具

以下名称和字段是本项目拟定契约，不是 MCP 官方内置工具，也不是已发布软件包的现成功能。

| 工具 | 主要用途 |
|---|---|
| `babel_content_check` | 检查运行时、扩展连接、目标所需依赖、目录和可用能力 |
| `babel_content_collect` | 提交内容采集目标，自动完成适配、必要页面操作和资料保存 |
| `babel_content_job_get` | 查询单任务阶段、进度、阻塞原因、完整性及结果 |
| `babel_content_job_resume` | 修复条件后复检并继续原任务 |
| `babel_content_job_cancel` | 取消任务并按规则清理临时资源 |
| `babel_content_jobs_list` | 列出当前客户端授权范围内的任务，支持分页 |
| `babel_content_browser_observe` | 查看指定任务或明确标签的页面摘要、候选内容和操作目标 |
| `babel_content_browser_act` | 对任务标签执行受限的导航、滚动、展开或播放等动作 |

正常任务优先只使用 `collect` 和任务查询。观察、操作工具是例外处理入口，不要求 Agent 每次点击几十次才能取得内容。

不暴露 `run_any_command`、`eval_arbitrary_js`、`dump_all_cookies` 等万能接口。依赖安装由外部 Agent 自己的终端工具负责，不通过本插件开放系统任意执行能力。

### 9.3 采集参数示例

以下 URL、目录、ID 均为示例，不是实际存在的任务或文件。

```json
{
  "target": {
    "type": "url",
    "url": "https://example.com/posts/example"
  },
  "include": ["text", "images"],
  "output": {
    "directory": "/Users/example/workspace/materials",
    "format": "bundle",
    "collision_policy": "version"
  },
  "browser": {
    "instance_ref": "paired-browser-1",
    "tab_strategy": "auto",
    "allow_focus": false
  },
  "limits": {
    "max_items": 1,
    "max_related_items": 0
  },
  "idempotency_key": "request-example-001"
}
```

参数约束建议：

- `target` 在 URL 和明确标签引用之间二选一，不接受任意含糊对象。
- `include` 指定文字、图片、视频、音频、字幕等需要的组成部分；用户只要文案时，不自动下载大视频。
- `output.directory` 必须在用户明确授权的路径范围内；相对路径基于已确认工作区解析，而不是进程碰巧所在目录。
- `tab_strategy` 默认 `auto`；是否抢焦点由明确策略控制。
- `limits` 是任务预算，不是抓取配额绕过手段。
- `idempotency_key` 用于重试去重，不能将同一调用变成多份重复下载。

平台许可与付费内容限制由服务端策略执行，不能由请求中的一个布尔参数关闭。

### 9.4 返回结构

短任务可以直接返回结果，长任务立即返回任务引用，Agent 后续查询。不要让一个 MCP 请求一直等待大型视频下载完成。

```json
{
  "job_id": "job-example-001",
  "status": "queued",
  "target_type": "post",
  "next_action": "poll_job",
  "poll_after_ms": 2000
}
```

`poll_after_ms` 是建议轮询间隔，由任务实际状态调整，不是最终完成时间承诺。

MCP 支持结构化工具结果 `structuredContent` 和工具执行错误 `isError`。本项目需要为成功、阻塞和错误定义稳定数据结构，而不是只返回一段人类说明。[R26]

### 9.5 内容返回与上下文预算

工具默认返回简短说明、元数据和本地路径，不把整篇长文、所有评论和视频二进制自动塞入上下文。

Agent 需要进一步阅读时，使用其已有本地文件能力。后续为不具备文件工具的客户端增加分页读取或 MCP 资源接口，不改变首版以本地 Agent 为中心的定位。

## 10. 环境诊断、依赖修复与续跑

### 10.1 最小能力永远不依赖完整下载环境

只要最小运行时与连接条件满足，MCP 工具发现、环境检测和不需额外引擎的基础内容读取就应该工作。

缺少 yt-dlp 或 FFmpeg 时，只影响真正用到它们的功能。不得在模块顶层强制导入或检查所有媒体工具，导致整个 MCP 启动失败。

### 10.2 按任务声明依赖

| 任务 | 依赖判断原则 |
|---|---|
| 读取普通正文 | 不需要媒体下载器、FFmpeg、OCR 或 ASR |
| 保存普通图片 | 使用已有 HTTP／浏览器能力，不强制装图集引擎 |
| 下载特定平台视频 | 检查该路径需要的引擎及其实际平台依赖 |
| 合并音视频 | 检查可执行的合并工具 |
| 仅保存平台字幕 | 检查字幕获取路径，不强制安装转录模型 |
| 本次无需的后备引擎 | 不检查、不预装 |

### 10.3 缺失依赖返回示例

下例是拟定的工具结果片段。诊断来源应是本项目可信依赖清单，而不是目标网页中的提示。

```json

    {
      "type": "text",
      "text": "任务暂停在音视频合并阶段，未找到可用的 FFmpeg。请由宿主 Agent 安装或指定路径后复检并续跑。"
    }
  ],
  "structuredContent": {
    "job_id": "job-example-002",
```

工具不能完成当前动作时可以返回工具执行错误；查询一个已经阻塞的任务本身是正常调用，查询结果中的 `status: blocked` 不必被当作协议故障。不要将业务错误做成无法让 Agent 阅读的连接崩溃。

### 10.4 外部 Agent 的处理约定

```text
收到结构化诊断
       ↓
确认这是依赖／配置问题，而不是权限或平台规则问题
       ↓
依据可信来源，在已有授权范围内安装或调整
       ↓
再次调用 babel_content_check
       ↓
运行时验证实际可执行文件与所需能力
       ↓
调用 babel_content_job_resume
```

插件提供需要什么、为什么需要、怎样验证；Agent 选择适合当前电脑的安装方式。不要在工具里搭建通用包管理器，也不要替 Agent 提前安装所有可能用到的软件。

### 10.5 安装成功不等于运行时能调用

Agent 的终端、浏览器启动的本机进程、容器或 WSL 可能不是同一执行上下文。方案应记录诊断上下文，并允许设置经过验证的可执行文件绝对路径。

复检必须由实际执行采集的运行时进行，而不仅是 Agent 自己运行一次 `--version`。PATH 或配置更新需要重载时，应返回明确提示；不能无休止地重复安装同一组件。

### 10.6 不应进入安装循环的错误

| 错误类别 | 后续行为 |
|---|---|
| `DEPENDENCY_MISSING`／`DEPENDENCY_INCOMPATIBLE` | 安装、替换或指定可信可执行文件，复检 |
| `BROWSER_OFFLINE`／`BRIDGE_UNREACHABLE` | 修复连接或启动正确浏览器，不安装媒体工具 |
| `LOGIN_REQUIRED` | 提示用户在正确浏览器中完成登录 |
| `PERMISSION_REQUIRED` | 仅申请任务必要权限 |
| `OUTPUT_NOT_WRITABLE` | 检查授权目录、磁盘和权限 |
| `TARGET_AMBIGUOUS` | 观察或确认具体目标，不随意选择第一项 |
| `RATE_LIMITED` | 按规则退避，不增加账号池绕过 |
| `PLATFORM_UNSUPPORTED`／`ADAPTER_NOT_ENABLED` | 报告当前支持范围，不自动切换成任意网站采集 |
| `ADAPTER_CHANGED` | 保存脱敏诊断，修复适配器并测试，不无限刷新 |
| `ACCESS_POLICY_BLOCKED`／`PAID_CONTENT_EXCLUDED` | 停止该路径，不以安装依赖继续 |
| `DRM_UNSUPPORTED` | 停止，不提供解密或绕过流程 |

### 10.7 修复不应破坏用户环境

默认使用用户级或项目级安装，保留已有 MCP 配置与工作区设置。需要管理员权限时明确说明，不静默提权，不关闭浏览器或系统安全策略，不禁用 TLS 校验，也不为了安装一个包全局放开不相关的脚本权限。

## 11. 任务状态与完整性

### 11.1 任务必须可恢复

任务状态不只保存在扩展 Service Worker 内存中。Chrome 扩展 Service Worker 存在生命周期与终止条件，任务数据应有持久化方案。[R24]

建议在本机运行时保存状态、阶段检查点、目标范围和输出清单。扩展保留必要任务映射；重连后与运行时核对，不能因为扩展重启就把已下载数据忘掉。

### 11.2 建议状态机

```text
queued → resolving → collecting → downloading → finalizing → verifying
             │            │             │             │
             └────────────┴──── blocked ─┴─────────────┘
                                  │ 修复并复检
                                  └── 返回可继续的阶段

终态：succeeded / partial / failed / cancelled
```

纯文字任务可跳过 `downloading`，无须合并的文件可跳过相关后处理。状态机不要求每个任务机械地经过全部阶段。

### 11.3 完成与部分完成分开

用户要求“文案和 8 张图”，取得文案但有 2 张图失败，应返回 `partial` 和失败明细。只有用户请求的必要组件全部完成且校验通过，才返回 `succeeded`。

无法知道页面还有多少内容时，记录 `completeness: unknown`，不能把“当前已经加载的部分”写成“全文”。评论、帖子串和无限滚动页面尤其需要这条规则。

### 11.4 重试与续跑规则

复用已有检查点，保留已完整保存的附件。媒体地址过期时在允许范围内重新解析；已下载音视频只缺合并工具时，补齐后从合并继续。

对同一已完成内容使用规范化来源标识和内容哈希去重。重试必须幂等；取消任务后不继续静默写入，不误删其他任务或用户文件。

### 11.5 进度与错误透明

只报告可测量阶段与进度。不知道总大小时不要给出虚假的百分比，不把网络等待表示为持续下载，不将进程退出码零作为唯一成功依据。

日志记录请求编号、适配器版本、阶段和脱敏错误，不记录 Cookie、完整授权请求头或带凭据的媒体地址。

## 12. 本地资料包与数据规范

### 12.1 标准交付是一份可继续处理的资料包

建议采用下面的目录结构。目录名是示例，实际文件由任务生成。

```text
materials/
└── source-id__safe-title/
    ├── content.md
    ├── metadata.json
    ├── assets.json
    ├── images/
    │   ├── 001.jpg
    │   └── 002.png
    ├── media/
    │   └── 001.mp4
    ├── subtitles/
    │   └── original.zh.vtt
    └── derived/
        └── README.md
```

`derived/` 可在后处理实际发生后再创建，不必给每个任务制造空目录。对于用户明确要求只要一个视频文件，也可以输出媒体文件和轻量来源旁车文件，不强制不必要的复杂目录。

### 12.2 各文件职责

| 文件 | 内容 |
|---|---|
| `content.md` | 原文、必要结构、相对附件引用；不是 AI 摘要 |
| `metadata.json` | 来源、作者、内容 ID、时间、类型、采集策略、完整性与版本 |
| `assets.json` | 附件顺序、角色、实际路径、媒体类型、大小、哈希、获取状态 |
| `images/`／`media/`／`subtitles/` | 请求保存且已实际取得的原始资料 |
| `derived/` | 外部 Agent 后续产生的 OCR、转录、摘要等派生结果 |

默认不保存完整网页会话、全部网络响应或含隐私的整页源码。排障确需快照时，单独启用并进行脱敏。

### 12.3 `ContentItem` 建议字段

| 字段 | 含义 |
|---|---|
| `schema_version` | 数据契约版本，便于其他模块兼容 |
| `content_id`／`platform`／`platform_content_id` | 统一 ID 与源平台标识 |
| `source_url` | 安全可引用的来源链接，不携带凭据 |
| `canonical_url` | 去重用规范链接，不误删识别内容所必需的参数 |
| `content_type` | article、post、thread、image_note、video、audio、mixed 等 |
| `title`／`authors` | 标题与作者；缺失时保留未知，不推断生成 |
| `published_at`／`captured_at` | 源发布时间与本次采集时间分开保存 |
| `language` | 原始语言；采集不默认翻译 |
| `blocks` | 有序文本、图片、视频、引用或帖子块 |
| `assets` | 附件引用，不内嵌大二进制 |
| `relations` | 作者续帖、引用、回复、父子内容等结构 |
| `access_class` | 内容可见性和免费／付费分类 |
| `policy_review` | 使用路径与平台规则审核状态，不等于自动获得版权许可 |
| `provenance` | 提取方式、适配器和运行时版本、必要的脱敏证据 |
| `completeness`／`warnings` | 全文、已加载部分、缺失附件及不确定性 |

`published_at` 无法确认时填写 `null`，不要用采集时间替代。帖子串中的不同作者分别标识；引用内容不归到发帖者名下。

### 12.4 文件结果返回示例

```json
{
  "job_id": "job-example-001",
  "status": "succeeded",
  "content_id": "content-example-001",
  "content_type": "article",
  "artifact_root": "/Users/example/workspace/materials/source-id__safe-title",
  "artifacts": [
    {
      "role": "primary_text",
      "path": "/Users/example/workspace/materials/source-id__safe-title/content.md",
      "media_type": "text/markdown"
    },
    {
      "role": "metadata",
      "path": "/Users/example/workspace/materials/source-id__safe-title/metadata.json",
      "media_type": "application/json"
    }
  ],
  "completeness": {
    "requested_components_complete": true,
    "scope": "single_item"
  },
  "warnings": [],
  "next_actions": ["read_local_files"]
}
```

这个示例只展示结构，不代表实际任务已经成功或这些路径已经存在。实际返回应附上已验证的附件清单，并确保其中每个文件真实可读。

### 12.5 目录安全与可移植性

文件名进行跨平台安全处理，避免重名覆盖和路径穿越。写入前验证目标位于授权根目录内，并考虑符号链接与 Windows 路径差异。临时文件完成校验后再原子化转为最终文件。

外部网页不能决定本地文件名为 `AGENTS.md`、启动脚本或项目配置文件，也不能覆盖现有代码。采集资料使用中性、受控名称，并明确标记其内容是外部数据，不是给 Agent 的工作指令。

本机路径只对相应本机执行环境有效。远端 Agent 的文件同步属于后续独立能力，不以一个 `file://` 地址假装已经完成传输。

## 13. 平台适配器

### 13.1 显式注册的平台适配器

平台适配器按支持清单显式注册，未启用或尚未验证的平台返回不支持／待验证状态，不静默交给通用网页爬取。

所有适配器输出相同的 `ContentItem` 和附件结果，使用相同的任务、诊断、目录和权限模块。平台变化优先落在适配器与测试中，不靠不断给 Agent 提示词增加补丁处理。

| 适配器职责 | 说明 |
|---|---|
| `match` | 识别域名、URL 与支持的内容类型 |
| `classifyAccess` | 判断公开性、付费属性及当前路径是否在启用范围内 |
| `probe` | 返回标题、作者、类型、候选内容与所需能力，不先下载全部资料 |
| `collect` | 获取目标范围内的正文和资源描述 |
| `requiredCapabilities` | 声明本次执行路径需要的浏览器或本机能力 |
| `validate` | 判断是否拿到了正确内容、是否截断、哪些附件缺失 |

适配器的方法名是内部设计建议，不必全部暴露为 MCP 工具。外部 Agent 仍然通过少量高层工具调用。

### 13.2 适配器发布元数据

每个平台维护内容范围、适配器版本、最后验证日期、测试样本、已知限制和规则审核状态。平台未经验证时标为 `experimental` 或 `review_required`，不要仅因域名匹配就显示“正式支持”。

正文选择器与媒体匹配规则可以版本化，但不得让网页下发任意可执行代码。扩展内执行的逻辑应随可信扩展版本交付；Manifest V3 对远程托管可执行代码存在限制，不能把远程下载脚本当成规避发布更新的手段。[R25]

### 13.3 不让回退路径越过范围检查

平台专项适配器判定“付费内容不接入”之后，不允许转给通用网页解析器或 yt-dlp 再试一次。所有执行路径，包括附件、重定向和后备引擎，都要经过同一内容范围检查。

“暂时识别不出内容类别”不等于“肯定免费”。应返回待核实状态，而不是扩大采集。

## 14. 安全、权限与隐私

### 14.1 只读内容产品，不带社交写操作

不提供发布、评论、点赞、关注、购买、发送私信等业务动作。浏览器点击仅用于已审核的内容展开、播放或导航。通用点击接口不能以“只读工具”的名字获得实际任意写权限。

### 14.2 浏览器权限按能力申请

首版围绕受支持的平台申请必要的网站权限。新增平台或启用敏感能力时可能仍需要一次明确授权；不承诺浏览器和操作系统永远不弹窗。

网络捕获、调试能力、Cookie 读取与任意站点权限不应不加区分地全部启用。普通文章读取不应顺带获得浏览历史、全部书签或全站会话导出权限。

### 14.3 登录态不交给模型保管

优先在浏览器上下文内使用会话。下载引擎确需会话资料时，只在扩展和本机运行时之间传递必要域名的信息，设置临时性、存储权限和清理机制。

MCP 返回 `session_ref`、任务编号或状态，不返回 Cookie、Token 或完整授权请求头。不能把某平台的凭据发送给无关 CDN、重定向目标或其他客户端任务。

### 14.4 本机服务也要认证

回环地址不是完整安全边界。本机 HTTP 接口需要验证客户端身份、来源与请求格式，避免任意网页借机触发本机操作；处理 Origin、Host、跨域请求和 DNS 重绑定等风险。MCP 传输规范也要求实现相应的来源与绑定限制。[R27]

首次配对应关联扩展实例和本机运行时，凭据保存于受控本地位置；欢迎页复制的安装提示不包含长期密钥。

### 14.5 把网页内容当数据，不当指令

采集页面中的“安装这个工具”“运行这段命令”“上传你的密钥”等文字全部属于不可信外部数据，不得进入依赖修复指令通道。

依赖来源只从本项目维护的可信清单、固定发布版本和校验机制读取。下载媒体不执行媒体目录内的脚本，不载入文章里伪造的 MCP 配置。

### 14.6 文件与网络限制

采集 URL 默认限制为任务范围内的 HTTP／HTTPS 内容；拒绝借媒体地址访问本机管理接口、内网敏感服务或无关文件协议。对重定向、清单片段和附件地址重新校验，不能只检查最初输入的 URL。

日志、元数据和错误摘要要移除签名凭据等敏感信息。需要保留来源参数用于识别时，区分可公开引用的来源链接和仅供当前请求使用的短期授权信息。

### 14.7 运行预算

给任务设置内容数量、附件大小、总容量、最长执行时间、页面操作次数和重试上限。数值根据实测与用户授权配置，不预设未经验证的吞吐或成功率。

暂停、取消和撤销接入应可用。减少人工是让正常流程顺畅，不是取消用户对本机行为的控制权。

### 14.8 边界只约束本工具

本项目可以约束自己的工具、运行时和执行路径，但不能保证一个具备独立终端能力的外部 Agent 永远不会执行本工具之外的行为。使用说明和返回结构要清楚，不把产品边界夸大为对宿主 Agent 的全局治理能力。

## 15. 开源项目与复用方案

### 15.1 怎么理解这份清单

以下为源码集成与实现参考，不是必须全部安装的依赖表，也不是已完成的依赖锁定或集成测试。项目资料沿用既有调研，采用前复核锁定版本的实现、许可证和维护状态。

“可复用”不意味着把每个项目都装上，也不意味着把全部代码搬进来。第一版只选择完成最小闭环所必需的模块，其他项目保留为专项参考。

| [Media Downloader Unleashed][R10] | 浏览器媒体扩展；MIT；项目明确说明不兼容 YouTube | 参考非平台专用的媒体发现与下载实现 | 不是统一引擎，浏览器适配需要单独测试 |

### 15.3 正文、图文与平台内容项目

| 项目 | 参考定位／既有许可记录（采用前复核） | 在 Babel Content Downloader 中的用法建议 | 取舍 |
|---|---|---|---|
| [Defuddle][R13] | 提取网页主体并输出清理后的 HTML／Markdown；MIT | 通用正文提取的第一验证对象 | 社交帖子需要验证专用结构，不能凭主张“any page”承诺全站 |
| [Mozilla Readability][R14] | 正文抽取库；Apache-2.0 | 对照测试或正文回退路径 | 不承担完整网页安全清理 |
| [Turndown][R15] | HTML 转 Markdown；MIT | 补充格式与自定义转换规则 | 不是正文识别器，也不是平台登录工具 |
| [Obsidian Web Clipper][R16] | 网页内容保存为 Markdown 的扩展；源码 MIT | 参考内容结构、模板和资料保存方式 | 不要求用户安装 Obsidian；不复制其商标和营销资产 |
| [xiaohongshu-mcp][R17] | 小红书 MCP；Apache-2.0；含帖子详情读取等能力 | 研究笔记标题、描述、图片及登录上下文 | 迁移只读部分；不全量引入发帖、评论、点赞等能力 |
| [twscrape][R18] | X 的 Python 数据访问库／CLI；MIT | 数据模型和字段结构参考 | 非浏览器扩展；不作为规避 X 规则的默认引擎 |
| [gallery-dl][R19] | 图集／集合下载；既有记录为 GPL-2.0，采用前核对具体许可及维护入口 | 后续特定图集的可选引擎 | 复核当前维护版本与具体许可证；不引入无限整站采集 |
| [Playwright MCP][R20] | 官方浏览器自动化 MCP；Apache-2.0 | 作为桥接与浏览器操作方案的对照和后备参考 | 仅作备选，不与主方案同时增加用户接入负担；按锁定版本验证登录会话复用 |

### 15.4 OmniGet 的复用边界

OmniGet 保留为整体集成参考，重点阅读浏览器扩展、本机桥接、任务及媒体处理模块。[R02]

但本项目不复制其“内容播放器＋课程下载＋工具大全＋学习功能”的整体产品形态。尤其上游存在的付费课程能力不属于 Babel Content Downloader 首版范围，不能因为源码现成就顺带开启。

### 15.5 首版最小组合

媒体下载器取得视频，并不等于保留了帖子文案、图片顺序、引用关系和作者信息。正文提取与平台内容建模必须单独实现。

最小组合建议收敛为：

```text
连接与浏览器操作：mcp-chrome 的相关模块
内容模型与任务：Babel Content Downloader 自己的轻量核心
已适配内容的正文：Defuddle；必要时以 Readability／Turndown 补充
社交内容：只读专项适配器
媒体获取：yt-dlp；按任务需要使用 FFmpeg
网络资源发现：研究猫抓，按许可证策略选择代码复用范围
```

其余项目作为专项后备与代码参考，不都变成默认运行依赖。

## 16. 许可证与分发检查

### 16.1 不先给整个项目贴 MIT 标签

mcp-chrome、Defuddle、Turndown 等许可较宽松；猫抓和 OmniGet 当前则是 GPL-3.0。直接合并不同来源的代码后，不能简单沿用最宽松的那个许可证。[R01][R02][R03][R13][R15]

本项目建议保持源码开放，但最终许可证应在确定实际复制、修改、链接和分发范围后落定。不能一边合并 GPL 代码，一边把整个衍生代码库未经评估地宣布为 MIT。

### 16.2 两条可执行的复用路线

| 路线 | 适用情形 | 对实施的影响 |
|---|---|---|
| 兼容强 copyleft 的直接整合路线 | 确定大量使用猫抓／OmniGet 代码，愿意遵守相应开源义务 | 做清晰来源记录、声明和源码交付；先核对全部组件兼容性 |
| 宽松许可核心路线 | 希望保持核心模块许可边界更清楚 | 优先复用 MIT／Apache 组件，对 GPL 项目以架构学习或合规的独立工具方式评估，不能照抄后改许可 |

两条路线都是工程和分发决策，不在未审计源码前擅自替用户定最终法律结论。需要在真正合并 GPL 模块之前完成选择，而不是等发布时再补。

### 16.3 分发核查项

- yt-dlp 仓库和 PyPI 分发的许可，与某些打包二进制的组合许可不是完全相同；上游明确说明部分 PyInstaller 发行物包含 GPLv3+ 代码。[R04]
- FFmpeg 的最终许可与构建选项有关，不应只写一个笼统的“免费开源”就忽略分发要求。[R05]
- Obsidian Web Clipper 的源码 MIT 不自动涵盖其商标、图标和营销资产。[R16]
- 让 Agent 在用户电脑上安装依赖，有助于减少本产品打包体积，但不意味着复制源码、联合分发或许可兼容问题自动消失。

### 16.4 开发时保留的证据

维护依赖锁文件、上游提交／版本、复制文件清单、修改记录、许可证文本和 `THIRD_PARTY_NOTICES`。不要仅记录仓库主分支链接，因为后续代码与许可可能变化。

本节是分发风险检查清单，不替代针对最终代码组合、分发地区与业务模式的专业审查。

## 17. 实施规划

规划按可验证交付物推进，不在没有开发估算与实际环境的情况下承诺工期。

### P0：先验证最关键的接入与范围

| 工作 | 验证结果 |
|---|---|
| 分析 mcp-chrome 可复用模块、桥接生命周期和许可 | 确定最小改造范围，不复制整个产品 |
| 使用 Babel Content Downloader 自己的扩展 ID 与最小运行时建立连接 | 真实浏览器端到端收发成功 |
| 验证 Codex 与 Claude Code 的接入 | 明确安装、配置、重载和授权差异 |
| 建立内容类型与平台范围检查 | 付费与非公开内容不会进入通用回退路径 |
| 选取有权限使用的本地测试页与公开测试内容 | 有可复现的正文、图片、视频样本 |
| 核对源码复用路线 | 合并前确认许可证边界 |

**阶段退出标准：**能够通过自己的 MCP 操作自己的扩展，完成一个明确、允许采集的目标；缺少媒体依赖时 MCP 仍可检查环境。

### P1：完成最小产品闭环

交付欢迎页与复制指令、Agent 接入说明、基础 MCP 工具、任务状态、资料包格式，以及至少一个经过访问条件与技术验证的内容来源，覆盖指定图文和一个免费视频获取路径。正文提取可先在自有测试页验证，但不将“任意公开网页”作为首版产品承诺。

同时验证缺少合并工具时的“返回诊断 → Agent 补齐 → 运行时复检 → 原任务续跑”，不能把环境修复只停留在文档里。

**阶段退出标准：**用户不操作下载按钮；Agent 能取得正文／附件和最终文件路径；正常结果与部分失败都有准确反馈。

### P2：补齐重点平台

优先处理用户明确提出的小红书、X，以及实际使用频繁的视频来源。每个平台分别完成内容范围与访问路径审核、数据结构、DOM／媒体适配、图片顺序和长文／帖子串测试。

X 的访问规则风险必须先解决，不把它默认为 P1 已支持。小红书同样需要账号实测和当前规则确认。技术无法稳定取得或访问路径不符合要求时，保留需求但不宣称上线可用。

### P3：稳定性与分发

补齐 Windows／macOS 的完整接入测试、多配置文件、浏览器重启、目录权限、任务冲突、组件升级、回滚和卸载。首版建议先聚焦 Chromium 系浏览器；Firefox、Safari、Linux 的完整支持按验证进度单独标注，不在安装说明里假设等价。

扩展商店版本与开发者加载版本的分发、扩展 ID 和权限行为分别测试。商店上架是否获准需要实际审核，不能把源码可加载等同于一定能上架。

### P4：后续扩展

根据实际缺口增加 N_m3u8DL-RE、图集引擎、更多已验证的免费公开平台、有限批量任务与 DSH 呈现层。课程作为后续可选内容类型，先验证允许获取的公开课程；付费课程及其他付费平台能力独立评估和显式启用，不列入首版交付。

### 首版不应被哪些事情拖住

不用先做账号体系、云服务器、桌面播放器、聊天面板、知识库、全文搜索和通用插件市场。先把“Agent 提交目标后，拿到完整可追溯资料”跑通。

### 19.3 可以直接交给开发 Agent 的总任务说明

这是开发说明，不是已可执行的安装命令。不要在项目尚未发布时编造 `npx babel-content-downloader` 等命令并让用户运行。

## 20. 首版非目标与后续扩展

### 20.1 首版不做

| 不做项 | 原因 |
|---|---|
| 人工下载列表和复杂资源选择界面 | 正常调用者是 Agent |
| 内置对话模型、API Key 管理和聊天窗口 | 复用外部 Agent，不重复造一层 |
| 完整通用依赖管理器 | 只做声明、诊断和复检，安装交给宿主 Agent |
| 课程专项适配 | 留待后续验证，首版优先自媒体内容 |
| 付费课程、会员专栏和订阅独享内容采集 | 首版明确排除，独立评估授权与平台规则 |
| 私信、好友限定和私密群组采集 | 不属于公开内容范围 |
| 自动发帖、评论、点赞或购买 | 不属于采集产品 |
| OCR／ASR／总结作为强制依赖 | 采集与后处理解耦 |
| 云端内容中转和账户托管 | 首版以本机与已有浏览器为中心 |
| 无限整站、全主页、全评论爬取 | 超出明确任务范围，增加风险和复杂度 |
| 每个平台一个独立下载器应用 | 统一适配器与资料包 |
| 为本机 Agent 再建一个通用工具执行器 | 不扩大任意代码与命令执行面 |

### 20.2 后续可以扩，但不自动继承当前授权

更多已适配的公开免费平台、明确范围的批量采集、其他浏览器、本地库导入、DSH 呈现层，以及经授权的课程和专业内容平台可以后续增加。主名和资料格式保持稳定，平台和内容类型通过适配器扩展。

付费平台扩展应有独立的访问路径与授权设计，不是简单增加几个域名或放开一个开关。非浏览器本地文件导入、EPUB／Word／PDF 解析属于邻接模块；Babel Content Downloader 可以在未来复用资料格式，但不必首版全部承包。
